## 里程碑插件 v2.5.2 第三轮：index.html 超 100KB，改为构建期压缩
- **结论：不能把 index.html 的代码迁到 plugin.js**。两个执行上下文（host 窗口里的 plugin.js vs iframe 全页视图里的 index.html）之间没有模块通道；index.html 必须是自包含文档（构建脚本本就禁止 `<script src>`，移动端是原生 WebView 整页加载）。靠 `parent.X` / postMessage 拼装会在跨域或移动端直接白屏，不可接受
- 正解：build.js 增加零依赖压缩器（`minifyJs` / `minifyCss`），只做「删注释 + 压空白」，**不改标识符、不合并行**（避开 ASI）。体积：index.html 111,059 → **84,841 字节（82.9 KB）**，plugin.js 58,953 → 39,466，安装包 51.6 → 36.3 KB，产物合计 165.6 → 122.7 KB
- 压缩器关键点：① 状态机区分字符串/模板串/正则，正则与除号靠「前一个有效字符是否为值 + 前一个标识符是否 return/typeof 等」判断；② 块注释删除后若两侧都是标识符字符要补一个空格（防 `a/*x*/b` 粘成 `ab`）；③ 行尾空格、行首缩进、连续空行、行内多空格全部收敛；④ 写盘前 `new vm.Script()` 重新解析，语法错直接构建失败
- 体积闸门：`index.html` / `plugin.js` 超过 100KB 构建直接失败（`BUILD_MINIFY=0` 时只警告，便于本地排查）；另拦住内联脚本里的 `</script>` / `<!--`（会截断 HTML）
- 出包兜底：`releases/*.zip` 常被压缩软件/资源管理器占着（Windows `EBUSY`），原来整个构建失败，现在改另存 `...-<timestamp>.zip` 并提示。**注意：被占用的文件连 `rm` 都删不掉，需先关闭占用**
- 新增 `test/minify.test.js`（已接入 `npm test`）：把压缩前后 bundle 放进两个独立 `vm` 沙箱逐函数比对 —— 1984 个日期的公历农历互转、1900-2100 抽样年 × 12 月 × 4 日、5 个基准日 × 6 类事件的 nextOccurrence/dateLabel/ageOn/yearsSince/cycleProgress/titleOf/dueReminders、parseYMD/颜色/节气/预设、宿主 `plan`；另有压缩器单元用例（字符串里的 `/`、正则字符类、除号、块注释留空格）。`static.test.js` 加 100KB 断言 + 「内联脚本已压缩」
- 视觉验证：Chrome headless 同参数截图，压缩前后**图片字节完全相同**（被工具判为同一张图）
- 复用经验：`build.js` 现在 `module.exports = { minifyJs, minifyCss, buildIndexHtml, buildPluginJs, read }`，`main()` 只在 `require.main === module` 时执行，测试可直接 require 构建脚本；`package.json` 的 test 脚本顺序 lunar → core → minify → build → dom → reminder-tasks → reminder → static
