# 里程碑

Super Productivity 插件。管理倒数日、纪念日、生日和节日，**支持农历换算与预设节日**，数据随应用同步在设备间流转。

## 功能

| 能力 | 说明 |
| --- | --- |
| 四种类型 | 生日、纪念日、倒数日、节日，各自有独立的计时语义 |
| 预设节日 | 18 个常用节日按公历 / 农历 / 节气分组，**可多选一次批量添加**；也可自定义节日 |
| 两种时间口径 | 倒数与生日显示**剩余天数**（橙黄），纪念日显示**已过天数**（蓝绿） |
| 时间排序 | 倒数越近越靠上，已过的越久越靠上；顶栏下的置顶卡片取当前分区的第一条 |
| 置顶卡片 | 可在设置里关掉，关掉后列表直接贴顶，一屏多看几条 |
| 年龄入名 | 生日在**显示时**于名称后加年龄，如「我妈生日（55岁）」；数据里只存纯名称 |
| 农历支持 | 农历生日/纪念日自动换算，每次打开都是当年对应的公历日期 |
| 闰月处理 | 闰月出生的人，在无闰月的年份自动按同月同日过 |
| 提醒进任务列表 | 每个日子可以单独选择是否生成任务；开着就插入，关掉就删除 |
| 提示条（可选） | 另一个独立渠道：每个日子可以单独选择「打开应用时弹一下」，与任务列表互不影响 |
| 归档 | 每个日子可归档：不在「全部」里显示，也不再提醒；筛选条最右边的「归档」就是归档视图的入口 |
| 周年显示 | 纪念日显示「7 周年」，跨年准确 |
| 深色模式 | 跟随应用主题，自动切换配色 |
| 跨设备同步 | 依赖应用自身的同步通道，桌面 / 移动端 / 网页数据一致 |

## 安装

**方式一：手动安装（推荐，各平台通用）**

1. 打开 Super Productivity → `设置` → `插件`
2. 点击 `Choose Plugin File`（选择插件文件）
3. 选中 `releases/plugin-milestone-v2.6.0.zip`
4. 安装后，左侧导航出现「里程碑」入口

> 不需要解压 ZIP。网页版因浏览器跨域限制无法自动下载，请手动下载 ZIP 后用同样方式安装。

**方式二：源码调试**

把 `dist/` 目录下的四个文件打包成 ZIP 再安装即可，`node build.js` 会自动生成。

## 使用

- 点击右上角「添加」，选择类型、历法、日期；右边的齿轮是设置
- **在某个分类下点添加，类型会自动选中该分类**：在「纪念日」里新建，类型默认就是纪念日；在「生日」里新建就是生日；「全部」视图下默认生日。类型仍可随时手动改，表单标题会跟着变
- 选择「农历」后，用年 / 月 / 日三个下拉框指定农历日期，下方会实时显示对应公历、干支与生肖
- 点击任意卡片可编辑或删除
- 顶部筛选条可按类型过滤；**「归档」是单独一个视图**

**关于节日**：类型选「节日」后，表单会多出一块「预设节日」选择区，分三组：

| 分组 | 节日 | 日期来源 |
| --- | --- | --- |
| 公历 | 元旦、情人节、妇女节、劳动节、儿童节、国庆节、圣诞节 | 固定月日 |
| 农历 | 除夕、春节、元宵节、龙抬头、端午节、七夕、中元节、中秋节、重阳节、腊八节 | 农历月日，每年公历日期不同 |
| 节气 | 清明 | 按节气公式推算，每年落在 4 月 4-5 日 |

- 选中一个预设，名称、历法、日期、颜色一次性填好，之后仍可改名称或换颜色
- **预设可以多选**：一次勾选几个节日，保存按钮会变成「添加 3 个」，点一下就按各自预设批量建好，不用反复新建
- 选「自定义节日」则不套预设：自己填名称和日期，一样每年倒数
- 节日与倒数日口径相同：显示**剩余天数**，过完自动滚到下一年的同一天
- 农历节日按农历算：今年中秋是九月二十五，明年就自动变成九月的另一个公历日
- **除夕按腊月最后一天计算**，腊月只有廿九天的年份自动按廿九，不会算错一天
- 清明的公历日期每年会漂移，保存的是「节气」而不是死日期，因此永远准

**为什么选中预设后历法、日期就不见了**：预设已经知道日期该怎么算，再摆一排下拉框只会有歧义。单选时名称仍可改；**多选时名称和颜色也收起**——一次加多个，每个节日用自己的名字和配色才是合理的。任何一步想手工改日期，点「自定义节日」即可，历法与日期控件会立刻出现。

**关于归档**：编辑任意日子时会看到「归档」开关（**节日没有这个开关**——节日每年都会再来，归档没有意义）。打开后这个日子：

- 不再出现在「全部」以及各个分类里，只出现在「归档」视图
- **不会再提醒**（任务列表里对应的任务会被删除，提示条也不会弹）
- 提醒配置本身会保留，取消归档后按原设置恢复

归档视图的入口是筛选条最右边的「归档」，后面会跟着数量（如「归档 3」）。点它即切到归档视图，点左边的「全部」就回来。在归档视图里点「添加」，新建的日子默认就是归档状态——这个入口就是给「不重要、只想记一下」的日子准备的。

**列表怎么读**：

- 右侧大数字 + 单位是该条目的时间口径。**剩余天数**（橙黄）表示还有多少天到日子；**已过天数**（蓝绿）表示从那天起已经走了多久，数字只会变大
- 排序：倒数类在上，剩余天数越少越靠上；已过类在下，已过天数越多越靠上。今天到点的条目剩余 0 天，自然排在最前
- 顶部的大卡片是「当前分区最靠前的那一条」：在「生日」里就是最近的生日，在「纪念日」里就是最久的那个纪念日
- 某个分区还没有记录时，卡片位置会保留一张虚线占位卡，切换分类不会出现页面塌陷
- 设置里可以关掉这张置顶卡片；关掉后列表直接贴顶

**关于倒数日过期**：编辑倒数日时有一个「**过期后重新开始倒数**」开关：

| 开关 | 过了那天之后 |
| --- | --- |
| 打开（默认） | 自动滚到明年的同一天，继续倒数，永远不会「过期」 |
| 关掉 | 停在原地，改显示「已过天数」，数字一天天变大 |

**过期后名称加删除线**：关掉上面那个开关的倒数日一旦过期，名称会划一条线（线比文字左右各长出一小截），类型标签也从「倒数日」换成灰底的「**过期的倒数日**」，一眼能看出这件事已经结束。不想要那条线，可在设置里关掉「倒数日过期后名称加删除线」——标签仍会标明过期。生日、纪念日、节日不受影响——它们要么每年重来，要么本来就是「已经走过多少天」。

**关于年龄**：年龄不写进名称字段，只在渲染时拼接。所以编辑时输入框里始终是「妈妈生日」这样的纯名称，做搜索、导出、排序都不会被年龄干扰；即使手动输入了「（55岁）」，保存时也会自动去掉，避免显示成两个括号。

**农历规则的细节**：农历腊月三十在某些年份只有廿九，闰月出生的人在无闰月年份按平月计算——这两处都会自动落位，不会出现「今年没有生日」。

### 提醒：两个渠道，每个日子单独选

提醒**不是**一个全局总开关。每个日子的编辑页里有两个独立开关：

| 开关 | 打开后的效果 | 关掉后的效果 |
| --- | --- | --- |
| 加入任务列表 | 在项目「里程碑提醒」里插入一条任务 | 对应任务立即被删除 |
| 打开应用时弹提示条 | 应用启动或跨天检查时若到点，弹一条 snack | 不弹 |

两个可以都开、只开一个、或者都关。都关时表单会明确写「这个日子不会提醒你」，不做静默失效。

**提前天数**（当天 / 1 / 3 / 7 / 30 天，可多选）对两个渠道共用：任务列表按最近的一档决定到期日，提示条在命中的那几天各弹一次。

任务的**到期日 = 该提醒你的那一天**。配「提前 3 天」，任务就在 3 天前到期。同一件事只占一条任务，不会每个档位各生成一条；某个档位过了，任务自动推进到下一个更近的档位。

任务长这样（类型用图标区分）：

```
🎂 妈妈生日（59岁）
生日 · 农历四月十八 · 每年
提前 3 天提醒 · 应处理日 2027-05-11
cd:ev=e1;cy=2027-05-14
```

最后一行是插件用的标记，别删它——跨设备靠它认出「这条任务是谁生成的」。删了也能在本机靠映射表补回。

**改、删都不留残骸。** 插件把任务当成数据的投影，数据一变就重新对账（保存后、启动时、每 10 分钟），逐条比对期望与实际：

| 你在插件里的操作 | 任务列表的反应 |
| --- | --- |
| 改名字 / 改日期 / 改提醒档位 | 同一条任务被就地更新，不会多出一条 |
| 关掉**这个日子**的「加入任务列表」 | 对应任务被删除，其他日子不受影响 |
| 把这个日子**归档** | 对应任务被删除 |
| 删除这个日子 | 对应任务被删除 |
| 在任务列表里勾选完成 | 本轮不再出现，直到下一年度周期 |
| 在任务列表里手动删掉任务 | 会被自动重建 |

⚠️ 最后一条是刻意的取舍：如果删任务就等于取消提醒，误删一次就再也收不到。要真正取消某个日子的任务，请回到该日子的编辑页关掉「加入任务列表」。

### 提示条

提示条是**每个日子各自决定**的，不是全局开关。打开某个日子的「打开应用时弹提示条」后：

- 多条同时到点合并成一条，例如「今天 · 我妈生日（59岁）｜明天 · 项目上线」
- 同一天同一档位只提醒一次，重启应用不重复
- 只在应用被打开或正在运行时出现——插件没有系统级推送权限，应用没开就不会有提示

**任务列表方式的实际好处**：任务的到期日跟着应用数据一起同步，你什么时候打开应用都能看到到期甚至逾期的任务，而不是「那一刻没开应用就永远错过」。

## 数据与同步

- 数据通过插件同步存储 API 写入，跟随应用配置的同步方式（SuperSync / Dropbox / WebDAV 等），不需要单独登录
- 远程数据变更时会自动刷新界面并提示
- 所有数据为纯 JSON，可随应用「导出数据」一起备份

数据结构：

```json
{
  "version": 6,
  "settings": {
    "taskProject": "里程碑提醒",
    "hero": true,
    "strikeExpired": true
  },
  "events": [
    {
      "id": "e1",
      "title": "妈妈生日",
      "kind": "birthday",
      "calendar": "lunar",
      "date": "1968-05-14",
      "lunar": { "year": 1968, "month": 4, "day": 18, "isLeap": false },
      "term": null,
      "preset": null,
      "repeat": true,
      "color": "#d6336c",
      "note": "",
      "remind": { "task": true, "snack": false, "offsets": [0, 1, 3] },
      "archived": false
    },
    {
      "id": "e2",
      "title": "中秋节",
      "kind": "festival",
      "calendar": "lunar",
      "date": "2026-09-25",
      "lunar": { "year": 2026, "month": 8, "day": 15, "isLeap": false },
      "term": null,
      "preset": "zhongqiu",
      "repeat": true,
      "color": "#7048e8",
      "note": "",
      "remind": { "task": true, "snack": true, "offsets": [0, 1, 7] },
      "archived": false
    }
  ]
}
```

`kind` 取 `birthday` / `anniversary` / `countdown` / `festival`（节日）。

`preset` 是预设节日标识（如 `zhongqiu`），自定义节日为 `null`；`term` 是节气标识（目前只有 `qingming`），有值时日期由公式推算而不是读 `date`。两个字段都只是**记录来源**，删掉也不影响显示 —— 农历节日仍按 `lunar`、节气仍按 `term` 算。

`remind` 是**每个日子自己的**提醒配置：

- `remind.task`：是否加入任务列表，默认 `true`
- `remind.snack`：是否在打开应用时弹提示条，默认 `false`
- `remind.offsets`：提前天数，取值限定 `0 / 1 / 3 / 7 / 30`，默认 `[0, 1]`

`archived` 为 `true` 时该日子只出现在归档视图，且不产生任务、不弹提示条。

`settings` 只剩三项：

- `taskProject`：任务归属的项目名，默认「里程碑提醒」
- `hero`：顶栏下方是否放大显示当前分区的第一条，默认 `true`
- `strikeExpired`：倒数日过期后名称是否加删除线，默认 `true`

> 插件的机器标识是 `plugin-milestone`（与 `package.json` 的 `name`、安装包文件名同一份），显示名是「里程碑」。详见下方[命名约定](#命名约定)。

`remind` 缺省时按 `{ task: true, snack: false, offsets: [0, 1] }` 补齐，新日子也用这一份默认值。

> **数据格式不向后兼容**：插件尚未对外发布，只保证当前格式（`version: 6`）可读。旧字段（`settings.taskSync` / `settings.snackOnOpen` / `settings.leapPolicy`、`remind.on`、事件的 `pinned`、`repeat: "yearly"`）会被直接忽略，不做折算迁移。真需要从很旧的备份恢复，可在设置里「清除里程碑数据缓存」后重新录入。

`title` 存的是纯名称，不含年龄、周年等展示信息——这些都在渲染时按当前日期计算并拼接，因此跨年后不会出现「55岁」被写死的情况。

### 清除数据

设置面板最下方的「清除里程碑数据缓存」是给升级后排查问题用的（数据错乱、任务重复、日期算错）：

1. 点按钮 → 第一段确认说明影响面：清空全部日子与设置、移除插件在任务列表里生成的提醒任务
2. 再点「确定清除」→ 才真正执行。中途任何一步点「取消」都不会改动任何数据

执行时会做三件事：把同步数据重置为 `{ version: 6, events: [] }`、清掉本机的任务映射表 / 已提示记录 / 已处理记录、**立刻写盘**（不等 200ms 防抖，避免刚清空又被旧值同步回来）。之后的下一次对账会把插件生成的任务全部移除——应用里的其他任务与项目不受影响。

清空后可以立刻继续新建日子，不需要重装插件。

## 平台支持

| 平台 | 状态 | 说明 |
| --- | --- | --- |
| Windows / macOS / Linux | ✅ | 桌面端完整功能 |
| Android | ✅ | iframe 全页视图，适配安全区 |
| iOS | ✅ | 同上 |
| 网页版 | ✅ | 手动安装 ZIP |

实现上刻意规避了平台差异：UI 走 iframe 全页视图（各端同一套渲染路径），不依赖 Node API、不引用任何 CDN 资源、不使用可选链等较新语法，也不调用 `crypto.randomUUID`。

## 已知边界

- 农历数据覆盖 **1900–2100** 年。超出范围的日子显示「超出可算年限」，不会崩溃
- 农历换算采用 1900-01-31 为基准的累积天数查表算法，已用 73,384 天逐日往返校验、201 个农历年天数校验
- **提醒不会主动推送**：任务列表方式下任务会按时出现在列表里，但「到点弹通知」仍需应用在运行；插件没有系统级后台推送与常驻能力（宿主设计限制）
- **卸载插件不会清理已生成的任务**：卸载/禁用后任务会留在提醒项目里（项目名见设置页，默认「里程碑提醒」）。卸载前把各个日子的「加入任务列表」关掉，或卸载后直接删除该项目
- 任务备注里的 `cd:ev=…` 标记是识别依据；跨设备时如果备注被清空，可能会多出一条重复任务（下次对账会删掉多余的那条）
- 任务同步需要宿主提供任务 API（`getAppState` / `addTask` / `updateTask` / `deleteTask`）。过旧的版本会自动降级为「只有提示条」，不会报错

## 开发

```bash
npm install        # 只有测试需要 jsdom
npm run build      # 生成 dist/ 与 releases/*.zip，并更新 preview/demo.html
npm test           # 农历 + 业务逻辑 + 压缩保真 + DOM 交互 + 任务投影 + 宿主调度 + 静态检查
npm run demo       # 在浏览器中打开预览页
```

**关于体积**：宿主对**单个插件文件**有 100KB 上限。`index.html` 必须是自包含文档（样式与脚本都内联，不能 `<script src>`——移动端是原生 WebView 整页加载，没有可用的模块通道），所以构建时会对内联的 CSS / JS 做「**删注释 + 压空白**」：不改标识符、不合并行（避开 ASI），并在写盘前用 V8 重新解析校验。未压缩 `index.html` 108.5 KB → 压缩后 **82.9 KB**，`plugin.js` 58.9 → 38.5 KB。

排查线上问题时想要可读版本：`BUILD_MINIFY=0 npm run build`（会超 100KB，仅本地查看用，不会拦构建但会警告）。`npm test` 里的 `test/minify.test.js` 会把压缩前后的逻辑逐函数比对（1984 个日期、全量推算、宿主对账），压缩若改坏了行为会直接失败。

源码结构：

```
src/
├── lunar.js        农历换算（1900-2100，含闰月）
├── event-core.js   数据模型、下一次发生时间推算
├── reminder-tasks.js  提醒→任务的投影与对账（纯函数）
├── app.js          iframe 内的界面逻辑
├── styles.css      样式（跟随宿主主题变量）
├── index.tpl.html  HTML 模板
├── plugin-main.js  宿主侧：入口注册、任务对账、可选提示条
├── manifest.json   插件清单
└── icon.svg        图标
build.js            打包脚本（零依赖，内含 ZIP 写入器）
test/               七组测试
```

### 命名约定

一个项目只允许**一个机器标识**，其余名字都从它派生：

| 用途 | 值 | 来源 |
| --- | --- | --- |
| 机器标识（`manifest.id`） | `plugin-milestone` | 唯一真源 |
| 安装包文件名 | `plugin-milestone-v<版本>.zip` | `manifest.id` + `manifest.version` |
| `package.json` 的 `name` | `plugin-milestone` | 必须与 `manifest.id` 相同 |
| 显示名（左侧导航、标题、设置关于） | 里程碑 | `manifest.name` |
| 提醒任务默认项目名 | 里程碑提醒 | `settings.taskProject` |

`npm run build` 会先校验 `package.json` 的 `name` / `version` 与 `manifest.json` 一致，不一致直接失败——避免再出现「包名一个、清单一个、版本还各走各的」这种漂移。

> 内部还有一层 `cd-` 前缀（CSS 类名、CSS 变量、`localStorage` 键、`data-cd-theme`）。它是 **c**ount**d**own 的缩写，属于界面命名空间，不是插件标识，与上面的身份无关；换掉要动 700 多处且无功能收益，因此保持不变。

改动后务必跑 `npm test`——DOM 用例会真的执行表单交互和同步写入。

仓库里带了一套 VSCode 配置（`.vscode/`）：打开任意测试文件按 F5 就会先构建再调试该文件，
也可以在调试面板选「跑全部测试」或「构建插件包」。`dist/` 与 `preview/` 是生成物，已设为只读提示，
改代码请改 `src/` 下对应文件。

## 上架社区插件列表

向上游仓库的 `src/assets/community-plugins.json` 提交 PR，加入：

```json
{
  "name": "里程碑",
  "shortDescription": "倒数日、纪念日、生日与节日管理，内置农历节日预设，支持跨设备同步。",
  "url": "https://github.com/<you>/plugin-milestone",
  "author": "<you>",
  "id": "plugin-milestone",
  "release": {
    "version": "2.6.0",
    "downloadUrl": "https://github.com/<you>/plugin-milestone/releases/download/v2.6.0/plugin-milestone-v2.6.0.zip",
    "sha256": "3dde714306ba3972ea62c988b640585fcd72e1401b076a82f0b14b85cd437e7e"
  }
}
```

`id` 必须与 `manifest.json` 的 `id` 一致，`version` 必须与清单版本一致。`sha256` 由源码决定：构建时使用固定的 ZIP 时间戳，因此同样的源码重复构建得到同样的哈希（可重现构建），改代码后才会变。`node build.js` 会在终端打印当前值。
